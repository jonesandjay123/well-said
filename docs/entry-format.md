# 條目格式

主要資料是 UTF-8 Markdown。檔案頂端使用 YAML front matter，內文保留完整語境。複製 [entry.md](../templates/entry.md) 後，放進 `entries/<category>/<slug>.md`。

## 中繼資料

| 欄位 | 規則 |
| --- | --- |
| `id` | 全庫唯一、穩定的 `ws-` 加英文小寫連字號 ID；改分類不改 ID。 |
| `title` | 繁體中文情境標題。 |
| `category` | `taxonomy.json` 的其中一個鍵，必須等於所在目錄。 |
| `status` | `example` 為示意案例；`collected` 為已取得實際討論內容的收錄。 |
| `intents` / `scenes` / `audiences` / `tones` | 各為至少一項、不重複的字串清單；使用繁體中文詞彙。 |
| `created_at` | 此條目首次進入資料庫的日期，`"YYYY-MM-DD"`。 |
| `updated_at` | 最後一次實質修改日期；不早於 `created_at`。 |
| `sources` | 至少一個來源物件；再次補充時追加，勿覆蓋先前來源。 |

每個來源物件都包含下列欄位，日期一律加引號，未知討論日期使用真正的 YAML `null`（不是字串 `"null"`）：

| 來源欄位 | 規則 |
| --- | --- |
| `kind` | `origin-note`（原始構想）、`chatgpt`（討論）、`manual`（手動提供）。 |
| `title` | 可辨認的討論串或材料名稱。 |
| `locator` | 可定位的段落、問題原句、訊息摘要或使用者提供的訊息 ID。不要編造 ID。 |
| `url` | 若確有可用來源連結，填完整 `https://` / `http://` URL；否則 `null`。不為收錄擅自建立分享連結。 |
| `discussed_on` | 來源討論日；無從確認就填 `null`。同一批可以有不同討論日。 |
| `collected_on` | 這次把該來源收進 repo 的日期；新增來源時保留舊來源的收錄日。 |

來源討論日不能晚於收錄日；來源收錄日位於條目的建立日與更新日之間。日期以使用者時區為準，不從機器 UTC 日期猜測。

## 內文固定區塊

1. `## 情境`：對象、前後脈絡、原本想說的話、真正目的、避免的誤會。
2. `## 台詞版本`：保留來源中的版本；新生成的補充必須明示為本次整理新增。每句附語體、語氣、白話意思與使用提醒。
3. `## 選用建議`：整理者推薦及理由，清楚區別於使用者已選擇的版本。
4. `## 使用者回饋`：只記錄明確說過的偏好；沒有就寫「尚未記錄」，不能把助理推薦當成偏好。
5. `## 來源與整理註記`：說明未知資訊、是否為示例、改寫／增補內容與來源位置。年代與古文出處未核實時不可編造。

模板與 front matter 是機器檢查的契約；台詞表格是閱讀慣例。檢查工具不會判定古文正確性、來源連結可訪問性、繁簡用字或語意重複，這些由整理者複核。
