# 分類指南

本文件處理收錄後的查找。日常聊天依原話、對象、態度、古風程度與情境探索台詞，不需要使用者先選主分類；見[討論指南](conversation-guide.md)。

## 先問：這次說話要達成什麼？

主分類取決於溝通目的，不取決於台詞表面字眼。例如「也罷」可能是接受，也可能是結束爭論；要讀前後脈絡再決定。

每筆只放一個主分類。若有多個目的，以使用者最想達成的結果為主，其他用 `intents` 標籤表示。

| 容易重疊的類型 | 判斷方式 |
| --- | --- |
| 評價 vs 接受 | 「這個方案普通」是評價；「先照這個方案做」是接受。 |
| 拒絕 vs 界線 | 拒絕這次邀約是拒絕；要求往後別再這樣做是界線。 |
| 異議 vs 圓場 | 要釐清事實是異議；重點是緩和尷尬則是圓場。 |
| 關心 vs 安慰 | 主動問候是關心；回應對方的低落是安慰。 |

若一次討論有兩個可獨立使用、原意不同的情境，拆成兩筆，彼此可用 Markdown 連結。若只是同情境的新說法，補進原條目並追加來源，保留既有 ID。

## 四組標籤，各司其職

| 欄位 | 回答的問題 | 起始詞彙例子 |
| --- | --- | --- |
| `intents` | 更細的表達目的？ | 保留評價、不掃興、暫時接受、婉拒邀請 |
| `scenes` | 發生在什麼場合？ | 用餐、作客、職場、購物、出遊、線上聊天 |
| `audiences` | 對誰說？ | 朋友、伴侶、長輩、同事、對手、陌生人 |
| `tones` | 收錄了哪些語氣？ | 溫和、含蓄、冷淡、調侃、堅定、親近 |

優先沿用既有標籤。需要新標籤時可以新增，但不要同時建立「公司、辦公室、工作場合」這類同義詞；統一成「職場」。不確定場景／對象時可用「未明」，並在內文寫出未知之處，不補造關係。

`tones` 是條目內各版本的語氣聯集，不表示每句都適合使用；冒犯風險要在每個版本旁說明。「半文半白、現代精煉、濃厚文言」是句子的語體，放在台詞表格，不與語氣混為一談。

「極簡、溫雅、機智、半文半白」保留作候選的探索方向，可組合使用，不作四個主分類。使用者想要的態度與古風程度另記在情境和各輪設定，不能從台詞標籤倒推使用者的原始要求。

## 何時新增主分類？

先用既有分類。只有累積數筆內容後，確定既有目的都無法描述它們，才新增主分類，並同步調整 `taxonomy.json` 與 README。不要為每個新場景建一層目錄。

分類錯了可以搬動檔案並修改 `category`，但 `id` 不變；更新指向它的連結，再重建索引。檔名用描述情境的英文小寫連字號，不包含日期。
