# 批次收錄提示詞

以下整段可複製使用，將括號內容換成本次範圍：

---

請把這一批情境台詞討論整理進我的 well-said repo。

- Repo：`jonesandjay123/well-said`（或我本次指定的 checkout）。
- 本批範圍：[討論標題／連結／貼上的內容；明確列出本次要收的討論]。
- 收錄日期：[以我的時區填寫今天日期；若不確定請確認，勿當作原始討論日期]。

先閱讀 repo 的 `AGENTS.md`、`docs/entry-format.md`、`docs/taxonomy.md`、`templates/entry.md` 與現有條目，再整理。

請完成下列工作：

1. 核對本批範圍，列出實際能讀到的來源；無法讀到的明確列為待補，不可憑聊天標題或記憶補造內容，也不要宣稱已讀完所有專案討論。
2. 一個情境一筆，保留前後脈絡、原意、對象、多種說法、語氣與風險。只收有實際內容的條目。合併同情境的新版本，保留舊 ID 與所有來源；不同語境使用相同台詞不用強行合併。
3. 主目錄依溝通目的分類，場景、對象、細部目的、語氣以標籤表示，沿用既有詞彙。不建日期目錄。
4. 每個來源都記錄討論日與收錄日；原討論日未知填 `null`，不拿收錄日、檔案修改時間或猜測的日期代替。沒有連結時保留可定位的文字，不擅自建立公開分享連結。
5. 原討論中的版本與本次新補的版本分開標明。只把我明確說過的喜惡放進使用者回饋；助理推薦另外記錄。不偽造古文出處，也不把示例當成我的實際經歷。
6. 以角色稱呼替換不必要的個資，保留語境需要的關係與情緒即可。
7. 若能修改 repo，直接完成條目、重建索引並執行專案檢查；若不能，交付每筆完整 Markdown 及相對檔案路徑。不要只交付整理摘要。
8. 回報本次新增、合併、略過、待補資料及檢查結果。commit / push 依我當次指示執行，不把這份提示詞當成每次都已授權推送。
